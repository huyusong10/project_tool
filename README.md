# 项目管理系统

面向可信局域网的本地项目管理系统。以项目进展甘特图为主屏，自动计算需求状态、进度和风险，并提供模板排期、计划/实际 Gap、人员矩阵、归档管理和带 Token 认证的 MCP 服务。

## 主要能力

- 项目进展：KPI、可筛选的需求级甘特图，以及可展开的工作项明细。
- 自动管理：根据工作项日期和阻塞状态推导需求状态、加权进度与风险。
- 流程设计：支持开始偏移、工期、并行与交错，并可拖动调整工作项顺序。
- 轻量需求：新建时只需标题，负责人、流程、排期和辅助信息可后续补充。
- 多人协作：工作项默认一名主负责人，也可增加协作人员；并发分析计入每位参与者。
- 异常行动：从需求、工作项和问题实时推导待处理项，不额外维护状态。
- 人员矩阵：按项目和岗位管理人员，并通过并发分析子页面查看今日工作排行和工作日并发矩阵。
- 我的工作：普通用户集中查看本人主责与协作工作项、近期并发和完成趋势，并直接更新状态与进展。
- 账号权限：人员自动拥有账号；支持普通用户、按项目授权的项目经理和全局管理员。
- 系统管理：归档恢复与删除、备份恢复和删除、MCP Token 管理；操作日志独立查询。
- 多分辨率布局：页面、弹窗、表格和时间轴按容器宽度自适应，支持常见办公屏幕及高 DPI 缩放。

## 技术栈

TypeScript、React、Vite、Fastify、SQLite、Drizzle 和 ECharts。默认开发分支为 `dev`。

## 启动

1. 首次使用先运行 `npm install`，复制 `.env.example` 为 `.env`，再执行 `configure.ps1` 完成账号配置。
2. 双击 `start.bat`，或运行 `npm run build` 后执行 `npm start`。
3. 本机访问 `http://localhost:3210`；局域网其他电脑访问 `http://本机IP:3210`。
4. 未登录时只显示登录入口；登录后的可见与可写范围由账号角色决定。

内置账号为 `admin`，密码沿用首次配置时设置的密码。安装完成后建议立即运行：

```powershell
.\configure.ps1
```

该脚本会重置内置 `admin` 的密码及会话密钥。其他账号在“人员与权限”中维护，用户可点击右上角登录名修改自己的密码。当前使用HTTP，请仅在可信局域网中使用。

新增人员时会自动创建同名登录账号，初始密码为 `888888`，首次登录必须改密。项目经理权限按项目分配；管理员拥有全局管理权限，内置 `admin` 不能停用或降级。

禁止账号登录会注销已有会话，重新启用后须重新登录。人员停用或归档后，须先恢复人员，不能直接启用其账号；登录、REST 和 MCP 均检查人员状态。修改姓名或岗位不改变登录状态，也不注销会话。MCP Token 在停用期间不可用，账号及人员恢复后可继续使用尚未过期、未撤销的 Token。

独立验证环境须使用自己的 `.env`、数据库、备份目录和 Session 密钥。设置不同的 `PORT` 和 `SESSION_COOKIE_NAME`（例如 `3220`、`pm_session_3220`），避免开发代理连到主服务或不同端口互相覆盖登录 Cookie。开发代理读取本环境的 `PORT`，默认仍为 `3210`。测试数据库快照建立后不要反复覆盖。

Playwright 使用 `.playwright/` 下的独立构建产物和临时数据库，不覆盖常驻服务的 `dist`、`dist-server`。`WEB_DIST_DIR` 指定测试服务的静态目录，普通启动默认仍读取 `dist`。

## MCP

登录后进入“个人设置”，创建Token并立即复制。Token自动继承当前账号的项目权限。MCP地址：

```text
http://本机IP:3210/mcp
```

客户端请求头：

```text
Authorization: Bearer pm_xxx_xxx
```

MCP覆盖需求、工作项、问题、行动项、我的工作、项目成员、流程和业务分析，与REST共用输入校验、权限和业务错误。不开放登录凭据、密码、Token管理、备份恢复、品牌及系统管理。

工作项、需求和进展支持独立分页查询；拓扑支持需求汇总、局部上下游、自动布局及 SVG 导出。工具选用、参数和批量图编辑示例见 [MCP 使用说明](docs/MCP.md)。

## 使用要点

- 新建需求只需标题；未填日期时保存为待规划，填入开始或截止日期时按流程自动生成工作项。
- 需求负责人可管理所属需求的工作项；验收、取消、归档和整体流程/排期仍由项目经理或管理员操作。
- 工作项通过“开始、完成、阻塞、解除阻塞、取消”推进；需求状态、加权进度和风险随之自动变化。
- 进展填写具体内容，可选关联工作项；只有进行中的工作项可以更新完成度，开始和解除阻塞使用独立操作。
- 需求详情和“我的工作”共用进展表单；工作项变更后保留输入并核对最新记录，工作项结束或移除不会把原进展自动转成需求说明。
- 需求详情、问题详情和“我的工作”后台刷新遇到网络或服务临时故障时，保留页面与草稿并提供重试；登录失效、无权限或记录不存在时清除该查询的旧数据，不继续展示旧详情。
- 进展录入收到无法解析的成功响应时保留输入，并提示先刷新核对实际记录；系统不自动重复提交写操作。
- 会话或项目列表临时刷新失败时保留页面与草稿，并提供重新加载；身份或权限变化时清除旧业务缓存，迟到响应不回填新账号页面。
- 历史需求可通过“操作 → 按计划完成并验收”补录；仅补录排期已结束且没有执行记录的工作项，保留已完成和已取消记录。
- 问题通过“确认解决”生成解决日期；纠错日期不能早于发现日期或晚于今天，重开会清空解决日期。
- 工作项实际日期不能晚于今天，实际完成不能早于实际开始；纠错只能引用同一工作项或问题的历史记录，原记录保持不变。
- 模板用“开始偏移＋工期”表达顺序、并行和交错；修改模板只影响之后的新需求。
- “人员矩阵”按当前项目和岗位分组；切换到“并发分析”可查看本周并按需加载后续周。
- 项目、需求、人员和模板归档后，可在“系统管理”的归档中心恢复或删除。

## 数据与备份

- 数据库：`data/project-manage.db`
- `.env`、数据库、备份、构建产物和依赖目录均不提交到 Git。
- 自动备份：按本地时间每日02:00执行，保留30天且最多保留100份（可通过 `BACKUP_MAX_COUNT` 调整）
- 手动备份、恢复和删除：登录后进入“系统管理”
- 升级使用编号迁移，不会重新初始化或覆盖现有数据库；升级前仍建议先执行在线备份
- 现有需求的“补全计划”显示保留已有日期后的结果，只填空缺日期，不覆盖已有计划和实际日期；开始晚于完成时不能应用
- 补全预览返回 `requirementVersion` 和 `previewToken`。REST/MCP 确认时应将其作为 `expectedVersion` 和 `previewToken` 原样提交；需求或流程变化后返回 409，须重新预览。旧客户端未传预览标识时保留原有版本校验
- 排期、延期、Gap、风险和并发分析统一使用 `chinese-days@1.5.9` 的中国法定节假日与调休数据（2004—2026）；超出范围时回退为周一至周五并在排期和甘特图提示
- 高风险延期阈值默认3天，可通过 `HIGH_RISK_DELAY_DAYS` 调整
- 每年年末检查 `chinese-days` 是否已发布下一年法定日历；升级后运行 `npm run verify` 并复核调休单测

## 常用命令

```powershell
npm run dev       # 前后端开发模式
npm run build     # 类型检查并构建
npm run lint      # 轻量代码检查
npm test          # 单元、集成和性能测试
npm run test:responsive # 六组常用视口的布局守护测试（使用本机 Edge）
npm run test:http # HTTP 非安全上下文：页面、登录、会话和流程草稿（使用本机 Edge）
npm run verify    # 原生依赖、代码检查、测试、HTTP 浏览器回归与生产构建
```

发布前运行 `npm run verify`。HTTP 回归使用普通测试域名，避免 localhost 的浏览器安全上下文例外掩盖局域网问题；不修改正式数据库。测试端口默认 3211，被占用时设置 `$env:PLAYWRIGHT_PORT='3241'` 后再运行。前端 UUID 统一使用 `src/client/random-uuid.ts`，lint 禁止绕过封装；新增依赖安全上下文的浏览器 API 时，须检测支持情况并补充 HTTP 回归。

需要开机自动启动时，以当前用户运行 `install-autostart.ps1`；移除时运行 `uninstall-autostart.ps1`。
