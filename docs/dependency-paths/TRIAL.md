访问：[http://127.0.0.1:3220](http://127.0.0.1:3220)。管理员访问资料在工作区 `.preview/access.txt`。

## 入口

| 页面 | 使用方法 |
|---|---|
| 侧边栏 → 路径分析 | 分析当前项目全部需求；默认突出关键及异常范围。点击余量分布筛选，选择节点后进入需求。 |
| 需求详情 → 需求进展 → 路径分析 | 展示内部工作项与外部交付点；默认以本需求验收为目标。由全局进入时保留项目目标。 |
| 需求路径 → 配置前置 | 选择前置交付点和后续工作。留空交付点表示整需求验收；留空后续工作表示整个需求开始。 |
| 需求路径 → 工期与预测 | 选择工作项后填写工期、最早开始、解阻日期或人工预测；不自动覆盖计划。 |
| 需求路径 → 预览排期 | 查看当前与建议日期，再应用到本需求及下游的未开始工作。进展变化、关系变化或跨日后旧预览失效。 |
| 流程设计 | 新流程维护前置和工期；支持接在后面、添加并行工作。旧偏移只能生成待核对建议。 |
| 项目进展 / 异常行动 | 复用服务端项目风险。甘特默认高→中→待评估→低；保留用户在当前视图选择的排序。 |

关系使用“完成后开始”，多个前置全部满足。提前开始需要记录执行例外；服务器校验工作项与依赖版本，保留原关系。源工作取消、未知解阻、未核对依赖、工期缺失、过期预测均会明确显示，受影响目标不输出确定交付日期。

两级视图使用同一份完整项目网络。局部目标只改变路径高亮与余量，不改变项目风险。需求级图汇总工作项关系，允许合法的需求级 A↔B；实际执行网络必须无环。

## 样例

| 项目 | 场景 |
|---|---|
| 交付依赖试用 | 接口交付→订单联调的部分交付；订单验收→版本发布的整需求约束；已知解阻假设、预测延期及未核对的待规划需求。 |
| 路径异常试用 | A 设计→B 开发→A 联调的合法往返；未知解阻、已取消的前置、等待验收、并列分支。 |

样例使用运行脚本当天的工作日。跨日后预测会重新计算；历史解阻假设过期时会转为待确认。种子脚本按项目名检查是否已创建，重复运行保留所有试用修改。

## 运行

所有命令在隔离工作区执行。

```powershell
Set-Location D:/tools/project-manage-paths
npm run build
npm run start:paths
```

开发前端：`npm run dev:web -- --host 127.0.0.1`，端口 `5174`，代理指向 `3220`。不要同时在同一端口启动第二个后端。
