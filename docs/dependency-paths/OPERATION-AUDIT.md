# 操作一致性核对

2026-09-09；基线 `a5807f4`。范围：需求详情、我的工作、甘特、路径草稿、验收、异常行动及对应服务。

## 本轮已修改

删除需求顶部“增加进展”。保留工作项完成度、直接执行需求进度及已有进展历史。工作项表单必须绑定明确的工作项，不再提供“不关联”或切换关联对象。

原入口默认只写 `progress_updates` 说明记录。只有选中进行中的工作项并提交完成度，才会更新工作项并汇总需求。这是入口含义与实际效果不一致，不能把文字说明当作完成度。

## 尚未修改的发现

## 后续整理边界

保持页面区域顺序和现有业务服务，不再建立新的流程层。

| 操作 | 唯一事实 | 保存方式 |
|---|---|---|
| 更新完成度 | 直接需求或指定工作项的百分比 | 执行命令，附说明 |
| 补充说明 | 指定对象的说明记录 | 不改变完成度、状态和日期 |
| 编辑范围、估算、关系和布局 | 项目编辑草稿 | 预览后整批保存 |
| 开始、完成、解阻、验收、纠错 | 执行事实与历史 | 先处理业务草稿，再提交明确命令 |

优先完成 1—4，再合并验收和结果核对入口，最后整理设置弹窗。服务端维护允许操作及原因，前端复用判断和表单；避免详情、我的工作、甘特各自重写一套规则。

保留已经成立的规则：分解需求进度从工作项汇总；工作完成先进入待验收；正式风险和优先级从完整网络计算；业务变更通过公共刷新函数更新各页面。筛选、布局和首页区域不需要为这次整理重新设计。
