## 使用规则

| 对象 | 操作与结果 |
|---|---|
| 交付范围 | 新需求默认纳入交付。经理可在需求管理批量调整，或在详情“交付设置”、画布属性中修改；进入共享草稿后保存生效 |
| 候选 | 不作为项目交付目标。已配置的依赖继续计算，阻塞正式交付时仍进入行动；开始前须先纳入交付 |
| 范围外执行 | 撤出已开始的需求须说明原因，保留进展、实际日期及关系 |
| 直接执行 | 新建时不选流程，直接在需求上开始、更新百分比、阻塞、解阻及提交验收，不生成隐藏工作项 |
| 分解执行 | 选定流程即生成工作项，日期可以留空。总进度由工作项汇总 |
| 后续拆分 | 详情“拆分剩余工作”，或内部画布拖入工作项后确认。保留已完成比例及实际开始日期，与新工作项一起保存 |
| 验收 | 默认项目经理，经理可指定有效成员。工作完成后仍须验收；代验操作者和说明保留在记录中 |
| 执行与草稿 | 编辑、预览不写正式业务表；执行命令要求先处理未保存业务草稿。普通返回、刷新继续保留本机草稿 |

拆分后进度 = 原进度 + 剩余比例 × 工作项完成比例。30% 后拆分，剩余工作完成一半显示 65%；按工期加权，界面沿用整数百分比。无工期的默认权重只用于进度，不能据此承诺交付日期。

阻塞需求先解阻、待验收需求先返工再拆分。删除末项不能切回直接执行，也不能将需求自动完成。

缺负责人、缺日期、缺工期属于资料提示。缺日期不阻止有效负责人开始工作；不可靠的预测显示待确认。

## 风险与处理顺序

执行事实、日期、依赖先计算最终风险，再计算处理优先级。旧人工 `priority` 不再参与风险或正式排序。

| 等级 | 首个匹配规则 |
|---|---|
| P0 紧急 | 关键交付阻塞，或驱动延期目标 |
| P1 高 | 其他高风险、全局关键工作、可靠缓冲不超过 2 个工作日 |
| P2 正常 | 中风险、待评估及其余有效交付事项 |
| P3 较低 | 已可靠评估为低风险、非关键且缓冲超过 2 个工作日 |

同级比较阻塞、影响需求数、风险、缓冲、交付日期、异常时间、稳定 ID；未知值放在已知值之后。结束需求退出活动排行；不影响交付的候选不参加默认行动排行。

需求管理保留日期默认排序，可选自动优先级。甘特和路径仍按风险优先；异常行动按自动优先级。局部路径目标、筛选及聚焦不改变正式结果。

Gap 阈值统一为 20% 中风险、50% 高风险。延期天数、关键路径及缓冲提升沿用现有规则。“按期交付”使用验收日期；实际结束日期表示工作完成。没有验收样本或计划日期时保持不可计算。

## 共同数据与接口

| 实现 | 责任 |
|---|---|
| `shared/delivery.ts`、`shared/domain.ts` | 范围、资料提示、进度、风险、自动优先级与排序 |
| `shared/paths.ts` | 完整项目网络、直接执行计算节点、目标、关键路径、交付影响 |
| `services/delivery-execution.ts` | 直接执行、拆分校验、范围及验收人权限、验收返工、日期调整 |

| `shared/delivery-impact.ts` | 同一快照修改前后目标、日期、范围、风险、优先级、缓冲、阻塞和责任变化 |

## 历史兼容

迁移 `0023_delivery_execution` 只增加需求字段。旧需求全部纳入交付；有任何工作项记录（含取消）保留分解方式，完全无工作项的需求采用直接执行。不补实际日期、验收、进展或工期；原依赖端点、布局、审计保持不变。

项目交付目标现在包含未排期的正式需求，原来被排除的需求会使预测转为待确认。这是目标范围变化，不能通过隐藏未排期需求恢复确定日期。

旧客户端未传 `executionMode` 时保留原模板展开行为。新版表单明确提交执行方式。旧 `priority` 接受兼容输入，仅保留为历史字段。

本机草稿继续使用原 IndexedDB 格式及对象 ID；缺少新字段从最新基线补齐。坐标、撤销历史和待核对批次保留。升级后的旧预览必须重新预览；结果未知的批次先查原回执，不重新创建批次。

异常关闭浏览器后，旧标签页的编辑权最多保留 45 秒；可以点击“接管此草稿”立即继续。正常返回不清除业务草稿。
