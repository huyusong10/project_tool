## 1. 目标与范围

用户维护工作和少数例外，系统计算依赖、排期、关键路径和风险。首个完整版本同时交付路径分析、风险提升、甘特图默认风险排序和专用分析页。[U1—U3]

| ID | 设计决定 | 来源 |
|---|---|---|
| SDS-SCOPE-01 | 支持同一项目内的需求依赖、需求内部及跨需求的工作项依赖；按目标分析它们组成的统一网络 | U1、U2；同项目范围为 [本篇] |
| SDS-SCOPE-02 | 模板预置内部依赖及工期；需求实例继承后可调整。日期与里程碑状态尽量由已有事实生成 | U2 |
| SDS-SCOPE-03 | 关键路径计算、可解释风险、默认排序、路径阻塞分析属于同一交付范围 | U3 |
| SDS-SCOPE-04 | 首版使用“完成后开始、全部前置满足”。跨项目关系、资源自动调平、复杂条件分支、通用画布编辑、Mermaid 导入和自然语言生成留待后续 | [本篇] |

## 3. 系统边界与责任

```mermaid
flowchart LR
    UI[浏览器页面] --> API[REST / MCP 权限入口]
    API --> W[业务写入与执行记录]
    W --> DB[(SQLite)]
    DB --> P[依赖与路径分析]
    P --> R[指标与风险汇总]
    R --> V[甘特图 / 异常行动 / 路径分析页]
    API --> P
```

图中的构建块是现有 Fastify 进程内的职责，不新增服务、图数据库或消息队列。[本篇]

| 构建块 ID | 唯一责任 | 消费者 |
|---|---|---|
| SDS-BB-01 业务写入与执行记录 | 模板、关系、工期、计划、实际记录、权限、审计和版本 | 分析、现有业务页面 |
| SDS-BB-02 依赖与路径分析 | 展开关系、校验循环、计算排期与预测、关键路径、余量、阻塞影响 | 风险汇总、排期预览、分析页 |
| SDS-BB-03 指标与风险汇总 | 合成自身风险与路径风险；提供统一排序和行动依据 | 首页、详情、列表、统计、REST/MCP |
| SDS-BB-04 业务页面 | 维护输入、呈现解释、调用已有操作；不自行定义风险算法 | 用户 |

运行与部署沿用 React、Fastify、SQLite、局域网及现有备份机制。外部客户端只通过现有认证 REST/MCP 访问；浏览器不直接读取数据库。[代码事实]

## 4. 系统约束

| ID | 规则 | 可验证结果 |
|---|---|---|
| SDS-XCUT-01 | 实际状态、计划、预测分别管理。分析是只读派生，应用排期才修改计划 | 分析、图上选择、刷新、预测变化均不修改计划和实际记录 |
| SDS-XCUT-02 | 页面、REST、MCP 使用相同权限、业务写入与分析服务 | 相同账号、项目版本、业务日期及分析范围得到相同结果 |
| SDS-XCUT-03 | 关键路径、影响和风险在完整授权项目网络上计算，再做显示筛选 | 隐藏上游节点不改变结果；不能通过跨项目引用泄露数据 |
| SDS-XCUT-04 | 关系只有一个权威写入位置；反向关系、需求汇总图和里程碑状态均为派生 | 修改工作项关系后不需要再手工修改需求关系图 |
| SDS-XCUT-05 | 未知工期、缺失关系、未知解除日期与已知风险分别表达 | 数据不足时不显示“无风险”“预计延期 0 天”或完整关键路径 |
| SDS-XCUT-06 | 风险计算不改变业务优先级，不把依赖等待自动写成执行阻塞 | P0—P3 与实际状态不因路径计算被覆盖 |
| SDS-XCUT-07 | 历史事实优先；归档保留依赖证据，取消不等于交付，返工触发重新分析 | 旧记录不丢失；受影响下游重新出现等待或异常 |
| SDS-XCUT-08 | 使用现有中国工作日日历，分析版本同时包含业务日期及日历版本 | 调休日、跨日刷新和超出日历覆盖范围的提示一致 |

## 5. 质量目标与验证

| ID | 目标 | 验证场景 / 度量 | 来源 |
|---|---|---|---|
| SDS-QG-01 | 减少重复输入 | 采用项目默认流程，录入标题和一个排期锚点即可生成内部关系与日期；录入负责人沿用现有操作 | U2 |
| SDS-QG-02 | 数字可复算 | 串行、并行、汇合、多条并列关键路径、部分交付、未知解除时间均有手工可核对样例 | U3、[本篇] |
| SDS-QG-03 | 多人修改不破坏图与计划 | 并发提交反向边只能有一个成功；旧排期预览拒绝应用；重试不产生重复关系 | [本篇] |
| SDS-QG-04 | 页面能直接定位待处理事项 | 阻塞排行点击后定位到源工作项、受影响目标和路径，能够跳回现有操作入口 | U3 |
| SDS-QG-05 | 控制计算成本 | [验收目标，未实测] 固定基准机上 2,000 工作项、6,000 显式依赖，单目标分析及前 20 个阻塞源汇总 p95 ≤ 1 秒；参考环境随压测结果记录 | [本篇] |

按需在服务端读取一致快照并计算。关键路径使用拓扑遍历，不枚举所有路径。首版无持久化分析历史、无周期任务；若压测未达 SDS-QG-05，再按项目分析版本添加可丢弃缓存。[本篇]

## 6. 跨模块运行规则

1. 修改依赖、模板实例、工期、状态、预测或日期后，业务写入在事务中更新相关版本及审计。
2. 分析服务从同一数据快照读取关系、工作、日期和权限范围，返回输入版本、业务日期及结果完整性。
3. 风险汇总合成最终风险，并把同一套原因交给列表、甘特图、统计和异常行动。
4. 用户预览排期时看到差异；应用时复核所有相关版本及权限，在事务中提交或整体拒绝。
5. 临时读取失败沿用现有页面保留旧数据与草稿的行为，并标注结果时间。身份或权限失效时清除旧数据，不能继续应用旧预览。

## 9. 取舍与剩余风险

- 只使用完成后开始关系。需要提前交付时拆出已有交付工作项，避免首版引入四种排期关系和复杂条件。
- 路径分析不做资源自动调平。人员同时承担多个工作项时，展示现有并发信息，不据此承诺可执行排期。CPM 与资源约束需要分别处理。[PMI](https://www.pmi.org/learning/library/scheduling-resource-leveling-project-progression-8006)
- 默认模板工期和按进度估算的剩余工期具有误差，所有预测保留来源。关键路径用于识别交付约束，其结果会随实际进展变化。[Microsoft](https://support.microsoft.com/en-us/project/manage-your-project-s-critical-path)
- 历史日期不能证明依赖；历史流程迁移需要一次预览核对。未完成核对的范围显示“依赖未核对”。
- 风险提升规则和“临近关键”的 2 个工作日阈值是本篇提出的首版默认值，不增加规则配置后台。
