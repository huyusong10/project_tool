## 3. 一套依赖事实，两种查看层级

### 3.1 依赖语义 MDS-DEC-01

| 用户表达 | 系统含义 |
|---|---|
| B 依赖 A | A 验收完成后，B 才具备开始条件 |
| B 的联调依赖 A 的接口交付 | A 的接口交付完成后，B 的联调才具备开始条件；B 的其他工作不受此边直接限制 |
| B 的联调依赖 A | A 验收后，B 的联调才具备开始条件 |
| B 依赖 A 的接口交付 | A 的接口交付完成后，B 才具备开始条件 |

所有显式边只有“完成后开始”一种语义，多个前置全部满足。首版不增加 OR 条件、开始后开始、负等待间隔。确有提前交付时，将成果落到一个工作项。[本篇]

计算时为需求生成开始点与验收点；内部结构把开始点连到全部内部入口，把全部有效工作项的完成汇合到验收点。需求开始点受外部前置约束，因此约束会传递到全部内部入口。工作项依赖连接前置完成与后续开始。

里程碑是某个工作项完成事件的名称，工期为零；复用该工作项身份，不建立另一份可手工完成的状态。多个成果汇合可由现有“联调验收”等工作项表达，不新建通用事件编辑器。[MDS-DEC-02]

验收点预计耗时默认为零，表示“假设完成后当日验收”；该假设必须出现在预测来源中。已有验收工作项时，它的工期正常计入。预测到达验收点不能替代真正的 `acceptedAt`。进入待验收后仍未验收且未给预计验收日期时，当前交付预测转为待确认。

没有有效工作项的未完成需求缺少执行模型，不能仅靠零工期验收点算成可以立即交付。作为前置被引用时向下游传播模型缺失。

### 3.2 聚合与校验 MDS-DEC-03

- 显式边保存一次，反向列表自动生成。跨需求工作项边自动汇总为需求之间的影响关系。
- 不把需求汇总边重新输入计算，避免重复约束和重复计时。需求总工期不能与内部工作项工期再次相加。
- 自环、重复边、非法端点、跨项目引用拒绝保存。循环检测在展开后的真实执行网络上完成。
- `A.设计 → B.开发 → A.联调` 是合法协作；需求汇总看似 A↔B，不能误判为执行循环。总览标记“分阶段协作”，展开后显示具体工作项。
- 取消的前置不能自动当成满足条件。已完成且归档的前置保留为已满足的历史事件。

## 4. 减少输入与模板排期

### 4.1 模板及实例 MDS-RUN-01

新增工作使用“接在后面”“添加并行工作”“等待其他工作”三个入口：分别添加当前项为前置、继承当前项前置、指定前置集合。并行表示无彼此先后约束，不强制同一时刻开始。拖动列表排序只改变展示顺序。

项目默认模板预置关系与工期。录入需求可以只写标题；进入排期时选择一个锚点，系统生成工作项、关系和日期。实例只修改不同于模板的部分，显示“继承模板”或“本需求调整”。模板升级不改变已有实例。

| 信息 | 默认来源 | 用户何时修改 |
|---|---|---|
| 工作项及前置 | 流程模板 | 本次执行顺序不同 |
| 预计工期 | 模板默认值 | 个别工作更大或更小 |
| 计划日期 | 依赖＋工期＋一个排期锚点＋工作日日历 | 必须约束开始日期时 |
| 实际进度与状态 | 现有开始、进展、完成操作 | 日常执行 |
| 预测完成 | 见 MDS-DEC-05 | 默认估算明显不合适时 |
| 预计解除等待 / 验收日期 | 无默认值 | 发生等待后，负责人已能给出时间 |

### 4.2 计划与预测 MDS-DEC-04

计划是已确认的安排；预测是当前事实下的结果。生成草稿时自动计算日期，用户应用后才变成计划。之后的依赖、工期或预测变化只重新计算预测及差异，不静默覆盖计划。

新计划默认向前计算：从开始锚点计算最早安排。按截止日期规划时反向计算可行的开始时间；若早于允许开始日期或今天，展示冲突，不能自动缩短工期或生成过去的未开始计划。默认不允许开始早于用户明确的“最早开始”约束。

普通计划开始/结束日期不是逐项锁定约束，否则自动排期无法移动工作。用户指定的需求开始锚点及主动设置的最早开始日期参与约束计算；自动推导的日期不成为新的锁定约束。截止日期用于判定目标差额，不强制压缩网络。

应用预览列出变动工作项、前后日期、变化原因及受影响需求。已经开始或完成的实际记录不可重排；实际开始固定，正在执行的计划调整不能改写该事实。未开始项可应用新的建议计划。

## 5. 关键路径分析

### 5.1 分析目标 MDS-DEC-05

默认目标为“当前项目已纳入计划的全部未结束需求完成”，系统生成汇合点，用户无需创建新对象。截止日期使用项目计划结束日期；未设置时仍可分析路径，但交付延期显示“未设目标日期”。

可切换到任一已有需求验收点或工作项里程碑，只分析通向该目标的全部前置。待规划需求列入覆盖说明，不偷偷排除后再声称整个项目可以如期完成。未指定负责人不妨碍数学计算，但仍保留现有责任缺失行动。

首页的常态关键性提升以项目默认目标为准。另检查各需求已有截止日期，若可靠预测显示会超期，则给实际导致该目标延期的驱动网络增加高风险。不能把每个需求的末尾工作仅按“对自身关键”提升全局风险，否则几乎所有需求都会被抬高。

切换到某个需求或里程碑只显示该目标的局部关键路径，不改变全局风险；局部关键标记与全局最终风险分别展示。首版不增加人工维护的交付目标清单。先在一次项目展开中计算各验收点的最早完成，再针对超期目标追溯驱动来源；不为全部节点枚举完整路径。

| 工作状态 | 当前预测依据 |
|---|---|
| 未开始 | 前置可用时间、明确的最早开始日期、今天和预计工期 |
| 进行中 | 保留实际开始；剩余工期默认 `max(1, ceil(预计工期 × (1 − 进度/100)))`，标注“按进度估算” |
| 人工设置预测完成 | 优先使用有效的 `forecastEnd`，记录当时的可开工边界及由此推算的剩余工期；前置以后延迟时保留这份剩余工期，不能靠缩短工作去迎合原预测日 |
| 阻塞且预计解除日期已知 | 从预计解除与前置可用时间中较晚者继续计算剩余工作；标注解除时间假设 |
| 阻塞且解除日期未知 | 当前分支预测未知，向后传播未知；不将今天或计划完成日当解除日期 |
| 已完成 | 使用实际完成，不再计入剩余工期 |
| 待验收 | 验收是独立交付条件；已给预计验收日期则使用，否则当前预测未知 |
| 已取消的前置 | 显示“前置成果已取消”，要求调整依赖；不得忽略后继续承诺交付 |

人工预测完成与解除日期均不能早于今天；非零工作量的预测完成必须晚于其可开工边界。前置解除未知时允许记录人工目标，但不当成确定预测。解除日期已过但仍阻塞，人工预测已过但未完成，立即标记过期，不继续作为有效未来预测。未知日期只影响其后续范围。

### 5.2 计算口径 MDS-DEC-06

统一使用工作日边界及半开区间：工期 `d`、开始边界 `ES`、完成边界 `EF = ES + d`。展示日期再转换为包含首尾工作日的日期，避免串行关系重复增加一天。零工期事件不额外占一个工作日。

对单个目标的有效无环网络：

```text
ES(v) = max(可用边界(v), max(EF(p)，p 为前置))
EF(v) = ES(v) + 剩余工期(v)
F     = 目标的最早完成边界
LF(目标) = F
LF(v) = min(LS(s)，s 为后续)
LS(v) = LF(v) − 剩余工期(v)
路径余量(v) = LS(v) − ES(v)
目标日期差额 = 目标截止边界 − F
```

完成事实作为已满足的固定边界，当前计算只保留剩余活动；同一套遍历可对已确认工期计算计划口径关键路径。计划口径使用当前已核对依赖，不代表某次历史图快照。实际已开始却仍存在未满足前置时，保留实际记录，标记“执行与依赖不一致”；该受影响分支不输出确定预测，待核对或调整关系。

路径余量为 0 的未结束工作位于当前关键网络；`0 < 余量 ≤ 2` 个工作日为临近关键。截止差额小于 0 表示预计超过目标，和路径余量分别展示。即使目标还有宽裕时间，也存在决定最早完成的关键网络。

所有并列关键分支都保留。连接关键节点的边还必须满足 `EF(前置) = ES(后续)` 才标为驱动边，不能把关键节点之间的所有连线都加粗。首版不枚举“所有完整路径”，只显示关键子图及可点选的代表链。

### 5.3 结果完整性 MDS-CONTRACT-03

共享结果必须携带：项目及输入版本、业务日期、目标与范围、日历版本、计划关键性与当前关键性、余量、预测来源、已知风险、未知原因、阻塞来源及去重影响集合。

- 工期缺失、关系未核对、前置取消或未知解除日期，均不能用 0 替代。
- 未知分支可展示已知部分的完成下界，但整个目标的预测日期、当前关键性和余量不能假装完整。已完整的独立目标仍可计算。
- 当前关键性未知时显示“计划关键 / 当前待确认”；计划关键网络来自已确认的计划模型。无计划模型则仅显示“待分析”。
- 未连接的历史工作项不自动视为独立任务，直到其所属流程完成依赖核对。
- 过滤负责人、状态、风险、折叠需求，只改变显示。隐藏前置显示数量和展开入口。

### 5.4 阻塞来源与影响 MDS-DEC-07

区分执行阻塞、等待前置、前置取消/缺失、预测过期、执行与依赖不一致。未来才开始且前置尚在正常执行，只显示等待条件，不进入异常排行。

等待达到计划开始边界，或预测前置交付晚于下游计划开始，才构成需要处理的依赖异常。沿未满足前置追溯到可处理的源工作项或验收点，后续等待节点不重复作为同一个根因。

存在两处独立执行阻塞时，两处都保留。例如上游接口等待审批、下游联调同时缺环境，解决审批不能自动解除环境阻塞。

“受影响需求数”按后续可达需求去重，排除源需求本身及已结束需求；“受影响目标数”按目标去重。“预计交付差额”来自完整网络，不把多个阻塞源的天数相加。除非重新计算了明确的假设场景，不显示“解决此项能提前 N 天”。

## 6. 风险合成与默认排序

### 6.1 风险口径 MDS-CONTRACT-04

`自身风险`沿用当前进度 Gap、已延期及执行阻塞规则。`路径风险`由关键性、前置异常和交付差额生成。`最终风险 = max(自身风险, 路径风险)`；P0—P3 不变。[U3、SDS-XCUT-06]

| 当前证据 | 路径风险规则 [本篇] |
|---|---|
| 在完整计算的项目默认目标关键网络上，运行正常 | 自身低→中，自身中→高，自身高保持高；理由包含目标名称及零余量 |
| 临近关键，余量在 1—2 个工作日 | 至少中风险；保留余量数值 |
| 关键工作发生执行阻塞，或到期仍被前置限制 | 高风险 |
| 目标预计延期，节点位于导致该目标延期的当前驱动网络 | 高风险，列明目标和预计差额 |
| 计划关键工作阻塞且解除时间未知 | 高风险，同时“当前路径待确认”；不显示伪精确延期天数 |
| 非关键上游延期，但余量足以吸收 | 不向所有下游复制高风险；各需求保留自身风险 |
| 依赖未核对或当前关键性未知 | 保留已知自身/路径风险，另标“分析不完整”；没有已知中高风险时显示“待评估” |

上表“自身风险”指所属需求在未叠加路径前的原有风险。关键性与阻塞定位到工作项，工作项产生的路径风险聚合到所属需求；同一需求包含多个关键工作也只提升一次。工作项卡显示所属需求最终风险及该工作项自己的关键性、阻塞信息，不新造另一套工作项风险评分。

已完成、已取消需求不再显示当前风险；待验收仍属未结束，必须参与路径风险，不能沿用当前代码对待验收的完全免评估处理。

阻塞解除后重新计算路径风险；保留仍存在的其他原因。自身风险升高与路径风险升高分别保留原因，不维护一个人工风险分数。

### 6.2 甘特图与行动 MDS-RUN-02

项目甘特图默认排序：未结束在前；最终风险高→中→待评估→低；同档按“关键阻塞源、其他关键、临近关键、其余”分组；再按已知最小余量升序、目标日期升序、优先级、稳定身份排序。未知余量在同组已知余量之后。已完成、已取消放末尾。

用户可以选择截止日期等其他排序；刷新数据不会强制改回默认。搜索首先过滤，之后仍遵循所选排序，不再用相关度覆盖默认的风险优先。需求内工作项默认保持流程顺序，支持切换风险排序，避免内部流程难以阅读。

甘特图使用风险颜色、关键路径标记和可展开的原因。关键性与风险不共用一种视觉编码；同一条低进度但不影响目标的分支，不会因位于图中央就被标成关键。

异常行动继续按源业务对象归并多个原因，增添路径理由和受影响范围。路径分析页中的阻塞源、异常行动和工作项详情使用同一源 ID；页面不新增另一套“处理完成”状态。

## 7. 路径分析页的共享信息设计

新入口位于工作台“项目进展”附近，名称“路径分析”，按当前项目显示。[本篇；具体布局为本轮可交互草图]

| 区域 | 回答的问题 | 数据与联动 |
|---|---|---|
| 目标与交付概况 | 分析哪次交付，现在能否预计完成 | 当前目标、目标日期、预测及来源、完整性；默认项目目标 |
| 依赖图 | 为什么这项工作影响交付 | 需求总览与工作项展开；默认聚合，不自动展开整张图；选中阻塞源展开对应需求并保留外部交付点 |
| 阻塞源排行 | 先处理谁 | 高风险优先，再按关键性、去重受影响目标数、等待时长；行内条形标示影响需求数 |
| 选中项详情 | 谁负责、等什么、影响谁 | 源工作项、原因、计划与预测、前置条件、受影响目标；链接现有操作 |
| 余量分布 | 哪些分支将变成关键 | 0、1—2、>2 工作日及待确认四组；点击筛选图和排行，不改变计算范围 |

图的语义：加粗边表示当前查看目标的关键驱动关系；节点风险标签表示全局最终风险；等待、执行阻塞和已完成用文字/图标区分。不能仅因处于关键网络就统一标红。已隐藏上下游显示数量。

默认以需求级显示关键与异常范围；切到全部可以查看完整网络。大图按需求聚合及逐级展开，不同时绘制数千个工作项。窄屏改为纵向路径和阻塞列表，选中详情位于下方；所有可点节点也有可用的列表入口。

选择排行项与选择图节点是同一个选择状态。复用现有开始、完成、阻塞、解除阻塞和进展表单；条件满足只更新提示，不自动开始工作或解除其他执行阻塞。

首版不增加路径数量饼图、综合健康分、趋势图。路径数量在分支汇合时容易膨胀；综合分难以解释；趋势图需要额外历史快照。若以后加入“解决此项后的效果”，必须使用完整网络情景重算。

### 7.1 查看层级与分析目标 MDS-DEC-08

“查看层级”只有需求级和工作项级，控制如何展开同一个分析结果。“分析目标”独立指定项目交付、需求验收或里程碑，控制计算终点。展开、返回、选择外部交付点均保留目标、数据版本、业务日期和全局最终风险。[U5、SDS-XCUT-03—04]

| 视图 | 节点与连线 | 用途 |
|---|---|---|
| 需求级 | 节点是需求，显示关键工作数/总数、最小工作项余量、整体预计完成及风险来源；连线汇总真实跨需求关系 | 看交付结构，找到需要展开的需求 |
| 工作项级 | 显示所选需求内部工作、依赖及必要的开始/验收点；外部前置和后续保留为边界节点 | 看具体等待条件和能处理的工作 |

需求节点“包含关键工作”不表示该需求所有工作都关键。节点整体完成时间与对外交付点日期分别展示；关键性、余量和交付预测只在展开网络中计算，不能拿需求总工期再跑一次 CPM。

需求之间同方向的多条关系按端点语义汇总，标记“整需求依赖 / 部分交付 / 混合”和原始边数。点开后可定位到每条真实关系。汇总边只要包含当前目标的驱动边，就标记“含关键关系”，不能据此声称整条需求序列是连续执行路径。

`A.接口交付 → B.联调` 展开后必须仍连接这两个工作项；`A.验收 → B.开始` 展开后必须保留需求边界，不能改写成某个工作项完成就放行整个 B。开始和验收的零工期节点属于计算/显示结构，不要求用户重复创建。

显示外部前置时，至少保留需求名、实际交付工作项或验收点、状态、交付时间与来源定位。点击外部节点可以继续展开来源需求；返回后恢复原有层级和选中项。下游已开始却前置未满足，仍沿用 MDS-DEC-06 的不一致规则。

需求汇总出现 A↔B 的分阶段协作时，标记真实的工作项阶段并支持展开；不强行按需求拓扑顺序排成一条链。风险排序用于列表和甘特图，图上位置由依赖结构决定。

### 7.2 连线与箭头 MDS-DEC-09

- 连线从明确端口出入；一个节点有多个前置时，分配不同的输入端口。汇入同一交付条件时才允许形成有标识的汇合。
- 箭头使用固定屏幕尺寸，约 7—8 像素；不随风险线宽同步变大。关键边仅适度加粗，普通边保持足够对比度。
- 连线路由预留间距并避开节点、端口标签和其他箭头；不能穿过卡片。默认采用正交折线，转角可小幅圆滑；圆滑处理不能破坏避障间距。
- 部分交付和整需求依赖通过文字与端点表达，不再新增一套容易混淆的风险线色。具体端点名称放在选中说明及关系明细中。
- 箭头尖端靠近目标边界，但与卡片保留约 4—6 像素间隙；分支不在同一段线上反复叠画，节点与线的层级保持稳定。
- 展开后保留选中对象，并以该对象恢复视口位置；返回优先恢复已缓存布局。结构变化允许当前可见图重排，不承诺布局器自动保持所有相邻节点不动。仅风险颜色、选中状态变化时不重新布局。

新增验收：需求总览→工作项展开→外部来源→返回过程中，目标、最终风险、预测时间保持一致；每条聚合边能还原真实端点；正常与关键箭头尺寸一致；桌面与窄屏均无连线穿卡、箭头重叠或裁切。

### 7.3 动态生成方案 MDS-DEC-10

当前 `path-analysis-levels.html` 的 `placeCards()` 为 A/B/C 示例预设位置，`drawEdges()` 根据卡片位置画线，没有通用避障搜索。已检查的 30 个页面状态只覆盖这些示例、宽度和主题；不证明任意业务图的布局质量。草图尚未接入自动布局器。[U6]

正式实现建议采用 React Flow（`@xyflow/react`）+ ELK.js（`elkjs`）。选型为本篇提案，动态样本验证尚未完成。

| 部分 | 责任 |
|---|---|
| 现有分析模块 | 根据完整工作项网络计算关键性、余量、交付预测和风险 |
| 视图转换 | 生成需求汇总图，或所选需求工作项及外部边界图；保留原始端点映射 |
| ELK Layered | 根据实际卡片尺寸、端口和关系，生成节点位置及连线路径 |
| React Flow | 显示业务卡片、自定义连线，处理缩放、平移、选择和定位 |

React Flow 官方文档将自动布局交给外部库；ELK 支持端口、正交路由及跨层关系，适合本篇的交付依赖图。Dagre 配置较少，但 React Flow 官方列出其跨子图连接的布局限制，本篇不优先采用。[React Flow 布局对比](https://reactflow.dev/learn/layouting/layouting)、[ELK Layered](https://eclipse.dev/elk/reference/algorithms/org-eclipse-elk-layered.html)

首版按第 7.1 节生成两种可见图，不要求同屏任意嵌套展开。图支持查看与定位，关系继续通过前置选择表单维护；不新增自由拖拽布图、手工拐点和位置保存功能。已有 ECharts 继续用于统计图表。[本篇]

接入规则：

1. 先测量卡片、可见边标签和端口，再提交布局。节点身份、输入顺序和布局参数保持稳定；风险或日期文本更新尽量不改变卡片外形。
2. 自定义边直接绘制 ELK 返回的起终点和拐点，正确转换坐标；不能只取节点位置，再用默认贝塞尔曲线替代已计算的路由。箭头方向取最后一段路径。[ELK JSON 边结构](https://eclipse.dev/elk/documentation/tooldevelopers/graphdatastructure/jsonformat.html)
3. 布局只消费展示结构，不修改依赖方向、业务日期或关键路径结果。需求汇总中的 A↔B 可以显示；真实工作项循环仍由业务层拒绝。
4. 图结构、节点尺寸或布局方向变化时重排。布局在 Worker 中运行，按输入版本丢弃过期结果；返回同一视图复用缓存和视口。ELK.js 支持 Web Worker，但是否能达到页面性能目标仍须实测。[ELK.js](https://github.com/kieler/elkjs)

实现前的动态验证使用无坐标输入，由引擎统一生成，禁止按样本身份补位置。覆盖分叉汇合、多前置、跨需求部分交付、需求级 A↔B、长标题、增删节点/依赖及两级切换。按 20、80、200 个可见节点记录布局耗时和交互表现；这组规模不代表已测得的产品上限。

验收分别检查节点重叠、连线穿卡、端口与箭头错位、标签遮挡、刷新跳动及布局失败后的列表入口。密集图允许不可消除的边交叉，通过聚合、局部展开和选中路径高亮降低阅读负担；不承诺任意网络零交叉。SDS-QG-05 的分析计算性能不替代图布局与浏览器渲染测试。

## 8. 写入、一致性与权限

### 8.1 公共写入规则 MDS-RUN-03

- 所有显式关系、实际记录、估算、计划与相关分析版本在同一 SQLite 写事务内更新。拿到写锁后再次检查权限、端点有效性和循环。
- 项目范围分析修订号覆盖依赖、实例工期、状态、实际日期、预测、目标日期、归档/恢复等所有影响分析的变更；展示排序变更不增加分析修订号。
- 新建边使用唯一端点组合，重复请求不新增；移除边按身份执行。其他命令沿用乐观版本检查，写入结果未知时读取最新结果核对，不盲目重提。
- 排期预览绑定项目分析修订号、实例版本、模板来源版本、业务日期及日历版本。相关输入变化返回冲突，保留草稿并重新预览；批量应用全部成功或全部回滚。
- 修改模板、跨需求依赖和已确认整体计划由项目经理/管理员执行。需求负责人可以维护本需求内部依赖，沿用现有工作项管理权限；不能创建或删除跨需求约束。工作项参与者仍能更新自身进展与阻塞预测。
- 新增 REST 与 MCP 行为共享校验和权限。旧接口、旧客户端不得通过数组覆盖或模板重放清除新关系。

开始工作时若前置未满足，显示原因并提供显式确认继续及记录说明；这属于一次执行例外，不删除依赖。服务端复核例外依据的版本，普通参与者可以记录自己的执行例外；其他依赖或权限限制不被绕过。完成记录反映事实，不因前置问题拒绝补录，但产生可追溯的不一致提醒。

### 8.2 归档、取消与返工 MDS-RUN-04

| 变更 | 依赖与分析行为 |
|---|---|
| 前置完成后归档 | 保留边及完成事实；后续仍满足条件 |
| 前置取消 | 不满足交付条件；相关目标预测待确认，产生一个源对象行动 |
| 取消后恢复 | 按恢复后的实际状态重新判定，不能默认视为完成 |
| 已完成工作返工 | 完成事件不再满足当前前置；未开始下游重新等待，已开始下游产生不一致提醒 |
| 删除被引用工作项 / 需求 | 有有效依赖时拒绝永久删除，提示先移除或改接关系；归档不删除关系 |
| 替换已被引用的流程实例 | 预览中逐条保留、改接或移除引用，任何未处理引用均拒绝应用 |

## 9. 历史兼容与迁移 MDS-MIG-01

1. 使用编号迁移新增关系、必要的估算/约束/来源信息及分析修订号，纳入现有备份。保留旧开始偏移、日期和历史记录。
2. 旧模板继续运行原排期模式。迁移时按已有偏移生成候选顺序与并行分支，必须预览核对；排序、同名或时间先后不能直接成为权威依赖。
3. 新模板使用依赖模式；旧模板经确认后生成新模式版本，已有实例不随之改变。
4. 旧需求维持日期；允许确认其现有前置，必要时明确“无前置”。可批量接受同一已核对模板，但必须匹配原模板版本、工作项映射及未修改范围，其余进入差异预览。
5. 未迁移范围继续自身风险及原甘特图，路径分析明确覆盖情况。没有关系记录不等于已确认独立。
6. 回退时关闭新分析及写入入口，继续读取既有计划，保留新字段和关系；旧版本服务禁止覆盖已迁移流程。若回退二进制，必须包含兼容保护；禁止恢复旧备份覆盖上线后的业务记录。

## 11. 可复算样例与验收

### 11.1 计算样例

以抽象工作日边界计算：A 为接口交付剩余 2 天，随后 B 为订单联调 3 天、C 为报表联调 2 天并行，B/C 完成后 D 为发布 1 天。各节点未开始，开始锚点为 0，目标截止边界为 6。

| 场景 | F | 当前关键网络 | 路径余量 / 目标差额 |
|---|---:|---|---|
| 无等待 | 6 | A→B→D | C 余量 1；目标差额 0 |
| A 已确认需要等待 2 天 | 8 | A→B→D | C 余量仍为 1；目标差额 −2 |
| C 工期改为 3 天 | 6 | A→B→D 与 A→C→D | B、C 余量均为 0；两条均显示 |
| A 解除日期未知 | 未知 | 计划关键 A→B→D；当前待确认 | 不显示确定的 F 或当前余量 |

“A 等待 2 天”是一次已知释放约束。不能同时把 2 天加到 A、B 和 D 上，亦不能把各阻塞原因的延误相加。
