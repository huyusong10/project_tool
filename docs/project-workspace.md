# 项目工作区

项目工作区分为关系图、进展表。首次进入显示关系图，进展按特性与 Phase 分区，默认展开到需求。

| 原能力 | 新入口 | 编辑与保存 |
|---|---|---|
| 特性、Phase | 关系图及对象详情 | 既有版本化接口 |
| 需求录入、导入、批量维护 | 清单工具和“录入与导入” | 既有表单、导入回执与批量版本检查 |
| 结构、依赖、布局 | 关系图及共用详情 | 项目草稿，预览后保存 |
| 需求与工作项排期、执行 | 进展表、我的工作、对象详情 | 既有独立提交与草稿冲突检查 |
| 提测、交付、返工 | 共用对象详情 | 既有执行规则和历史记录 |
| 统计分析、异常行动 | 进展辅助入口 | 沿用全项目口径，返回恢复原范围 |
| 人员矩阵、流程设计、设置、日志 | 项目配置 | 沿用原权限 |
| 独立需求详情 | 原链接 | 共用对象内容，不嵌套执行工作台 |

Phase 排列只表达范围。执行状态、交付记录和快照取正式数据；草稿显示未保存标记。只移动布局时保留已有交付判断、预计日期和余量，预览暂时不可用也不将交付条件标为待确认。

| 任务 | 首次展示 | 详情默认内容 |
|---|---|---|
| 关系图 | 特性关系图；清单展示目标、完成标准、分解与归属 | 资料与分解 |
| 进展表 | 特性及 Phase 分区，默认显示需求；按需展开工作项 | 安排与执行；选中工作项时优先显示其字段 |

两个任务共享对象选择、范围和项目草稿。图形视口、清单排序和甘特时间窗口分别记忆。切换任务先保留本机输入，不自动提交；无效字段也保留。执行操作检查正式数据及冲突草稿，纯布局修改不阻塞执行。

甘特使用上下双轨：上轨显示计划，下轨显示实际，并标注工作项百分比或需求阶段进度。月视图按月画网格，避免密集的每日竖线。名称和负责人固定在左侧，进展和操作固定在右侧。点击工作项百分比更新进度，行尾直接开始或完成。详情与甘特使用同一套执行组件。

左侧固定区宽 320px，较小办公窗口为 300px，只显示名称和负责人；没有负责人时显示“未分派”。右侧显示阶段、百分比及执行操作，并行阶段合并为“并行 · 分析设计 90% · 开发 17%”。完整排期和最近进展通过名称或甘特条摘要查看；未定日期的里程碑使用右侧“◇ 数量”入口。Phase 左侧显示名称和需求数量，状态在右侧。

特性行 34px、Phase 行 48px、普通需求及工作项约 50px，有日期里程碑的需求行 66px。需求右侧的“工作项”按钮带数量，点击展开或收起；Phase 提供交付详情。展开或更新进度时，左右固定区宽度不变。甘特只使用一条原生横向滚动条。

展开层级可选择 Phase、需求或工作项；选定单个特性时，面包屑保留名称，甘特省去重复特性行。默认按需求名称／编号自然排序，特性跟随其首条需求排列，空特性排在后面；“更多筛选”可切换为特性名称顺序。Phase 保留批次顺序，工作项按维护／模板顺序排列，更新进度不改变顺序。

未安排 Phase 的需求直接列在特性下，不增加中间行或文字标记。

筛选栏提供搜索、执行状态、人员和特性。“排除未开始”“尚未结束”“只看进行中”可直接选择，也可以多选执行状态；人员匹配负责人及工作项协作人。Phase、阶段、计划、归档、风险、时间和排序集中在“更多筛选”。弹层覆盖页面，不挤动表格。

执行状态和人员按每条工作自身匹配；保留祖先行，匹配项初始展开后仍可折叠。Phase 的完整状态不随筛选重算。筛选写入网址并按账号、项目记忆，“重置”清空条件，不重置时间轴和排序。

关系图先按依赖排列 Phase 内部卡片，再用实际卡片尺寸确定外框。保存的相对位置不会横向截断；拖动向右或向下时扩大外框，后续区域随之平移。自动整理仍需进入编辑，可撤销，不增加执行依赖。

甘特上层使用细描边计划条，下层使用实心实际条。百分比在固定列持续可见，条内空间足够时辅助显示；短条不塞文字，虚线不被标注遮挡。日视图按月份分组，网格弱化，统计日期保留。里程碑显示名称和日期标记，日期未定时提供查看入口。悬停或聚焦甘特条可以查看计划、实际、预测、等待前置和最近进展；摘要复用已加载报表，不逐行请求详情。

甘特中的特性没有总百分比。Phase 使用目标与实际交付节点；需求显示阶段，工作项显示自身进度。筛选保留祖先行，不重算 Phase 的完整交付状态。归档完成需求保留只读贡献；空 Phase 可查看维护，没有展开按钮。

进展不显示“需要关注”筛选、近期交付摘要行或“正式计划”按钮。旧关注条件在加载时移除。结构修改在关系图处理；有未保存或待核对结果时，原工具栏槽位显示处理入口。

公共工具栏固定返回、面包屑、任务切换、状态和操作槽位。状态使用文字与圆点，悬停或点击显示说明；状态与按钮之间有分隔线。多选操作放入已有工具行，窄屏浮在底部，不推移列表。主入口只保留“关系图／进展表”。特性、需求和工作项清单通过筛选栏右侧工具按钮进入，旧清单链接继续可用。详情覆盖主区域，不触发画布适配；展开最多 1080px，窄屏使用全屏详情。两种视图加载同一份详情样式，字段宽度、字号、间距和分区一致。

旧 `/features`、`/paths`、`/requirements` 分别进入特性清单、关系图及需求维护。`/execution`、`/analytics`、`/actions` 属于进展任务，独立需求链接继续可访问。

开发与验证在 `codex/project-workspace` 隔离分支完成，测试端口为 3271。发布使用主干 `dev` 和 3210 服务；交付后移除临时 worktree、3260 和 3270 服务，保留正式数据及发布备份。发布结果见 [本次发布记录](project-workspace-release.md)。

## 开发验证场景

以下场景使用隔离数据库中的演示项目，不写入正式项目。

1. 查看特性图，进入资产管理，比较 Phase 1 已交付、Phase 2 推进中、Phase 3 规划中的并行范围。
2. 进入测试需求，选中测试工作项，切换进展表。甘特展开并定位工作项，需求显示“测试中 · 70%”。返回关系图保留选择。
3. 展开平台集成验证，查看已归档需求的交付贡献，以及包含 60 个工作项的长标题需求。搜索单个工作项时保留其祖先。
4. 查看跨特性依赖；筛选单个 Phase 后仍可追查外部前置。拖动节点只改变布局。
5. 在关系图编辑工作项名称或阶段，切换任务查看草稿投影；返回关系图预览、保存或撤销。行内更新进度仍检查冲突草稿。
6. 在甘特选择“展开到工作项”，点击百分比填写进度；行尾可以开始或完成。点击名称再打开详情。
7. 从清单工具和“录入与导入”录入、导入或批量安排；从进展更多操作进入全项目分析，返回恢复原范围。

如需再次开发，先创建独立 worktree，再使用仓库中的预览启动和演示脚本；不要在正式目录启动测试服务。

问题跟踪在各宽度保留完整列，表头和内容一起横向滚动；分页栏保留在可见区域。小屏不隐藏最近进展，不改为卡片或增加第二行。特性清单的目标说明与名称左边缘对齐。

工作项详情展示协作人、计划与实际日期、预计完成、等待前置和阻塞说明；工作项设置保留人员、阶段、日期、排序和新增／删除。需求资料、提测、执行、纠错、归档、模板、依赖及历史入口保留。特性资料、评估、Phase 安排、交付和重新打开继续使用原接口。
