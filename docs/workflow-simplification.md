# 工作流简化方案

状态：2026-09-10 已发布到 3210 服务，网页、MCP 和本机录入技能同步更新。

## 目标

系统只围绕需求和可选工作项推进。原始需求直接成为需求，原文和出处保存在需求详情中。人员只维护要做的事、负责人、计划和进展。

```mermaid
flowchart LR
    A[录入或导入需求] --> B[安排负责人和计划]
    B --> C[开始并更新进展]
    C --> D[工作完成]
    B -. 多人协作时 .-> W[拆分工作项或套用模板]
    W --> C
```

## 已确定的删减

| 现有设计 | 简化后 |
|---|---|
| 待规划、未开始 | 合并为“未开始”；没有日期显示“未排期”，没有负责人显示“未分配”，均为资料提示 |
| 来源文档 → 条款 → 交付需求 → 工作项 | 原始需求直接录入为需求；只有需要分工时才拆工作项 |
| 条款目录、条款关联、落实范围、来源版本核对 | 移除独立模块；原文、原编号、来源链接并入需求说明 |
| 阻塞、解除阻塞、预计解阻日期、协调人、复查时间 | 移除；遇到困难仍处于进行中，说明写入进展，需协作的问题可关联已有问题记录 |

同一个需求可以有多个出处。只保存出处和原文，不要求用户再维护一套来源对象及其状态。

## 同步简化

| 现有设计 | 简化后 | 影响 |
|---|---|---|
| 待验收、确认完成 | 工作完成即完成；确有验收工作时，把它作为有负责人和计划的工作项 | 完成时间与工作事实一致；取消需求外的第二次完成操作 |
| 直接执行／工作项分解模式 | 界面只提供“添加工作项”和“套用模板” | 有工作项则自动汇总，无工作项则直接更新需求，不需要先选执行模式 |
| 候选／纳入交付 | 使用一个需求列表；未安排的需求保持未开始 | 取消候选转正和纳入交付操作；未排期需求仍需明确显示 |
| 首次承诺／最近承诺／当前计划 | 日常只使用当前计划，计划修改保留历史 | 不再并列展示多种按期率；历史承诺记录保留供查阅 |
| 预测核对、前置条件确认、提前开始确认 | 根据日期和依赖计算提示，不增加确认流程 | 前置未完成时提示；允许记录真实开始情况 |
| 风险等级和自动处理优先级 | 优先展示具体原因：已延期、预计晚于计划、排期不完整 | 减少解释评级规则的负担；关键路径仍可标出 |



## 状态和完成规则

主状态统一为：未开始 → 进行中 → 已完成。取消作为退出操作保留；返工将已完成项退回进行中，并保存原完成记录。

| 场景 | 规则 |
|---|---|
| 无工作项 | 直接开始、更新进展、完成需求 |
| 有工作项 | 需求进度由工作项汇总；全部有效工作项完成，需求自动完成 |
| 某工作项未按期完成，但其他工作仍在做 | 单项保留自身偏差；需求整体比较最后工作完成日期和需求计划结束日期 |
| 工作完成但稍后补录 | 使用填写的实际完成日期，不用录入日期或确认日期代替 |
| 缺负责人、缺计划 | 允许先录入，显示具体缺项；不引入“待规划”状态 |
| 遇到问题 | 记录进展或问题，继续使用进行中状态；不要求先解阻才能更新工作 |

取消项不计入进度和完成日期。只有取消项、没有有效工作项时，不自动判定完成。

工作项的“修正日期与说明”可更正实际日期，也可关联原执行记录补充更正说明。仅更正说明时保持日期、状态和完成度；原记录与更正记录同时保留。

已完成需求的延期 = 最后一个有效工作项实际完成日 − 需求计划结束日，按工作日计算。无工作项时使用需求实际完成日。未完成需求超过计划结束日时按当天计算。缺少计划或实际日期时显示缺项，不补造日期。

## 录入与页面

- 新建需求：先填标题和描述即可保存；负责人、日期可以随后补齐。原编号和来源链接为可选资料。
- 文档导入：直接预览将创建或更新的需求。人类可以逐项修改标题、原文、负责人和计划；保存后进入需求列表。
- 拆分需求：仅将能够独立安排和完成的内容拆开，保留原文和出处；不把每个段落、验收点、约束都变成新需求。
- 批量数据格式保留为导入工具，用户不需要理解条款标识、来源映射或 JSON 才能使用主流程。

| 入口 | 内容 |
|---|---|
| 项目概览 | 进度、延期、近期完成、排期缺项 |
| 需求 | 需求列表、详情、工作项；列表和甘特使用同一批数据 |
| 我的工作 | 当前人员的待做工作和进展更新 |
| 路径分析 | 查看和调整依赖、关键路径、受影响工作 |

问题、人员、模板和设置作为辅助入口。需求详情以描述、工作项和进展为主，来源放在资料中，不再单独展示来源与落实范围面板。

项目经理可在目标项目的流程设计中选择“复用已有流程”，从可读取的项目选择并预览来源流程。系统先生成独立草稿，保留工作、里程碑、依赖和工期；调整并保存后，目标项目的新需求可选用该流程。源流程、已有需求和项目默认流程保持不变。

## 路径分析保留的边界

保留工作项依赖、跨需求依赖、节点位置和人工布局。整需求的依赖端点改为工作完成，与列表、甘特及 MCP 使用相同完成规则。

取消人工阻塞状态后，图仍能显示“前置尚未完成”和日期影响。等待前置是一项计算提示，不再要求用户执行阻塞、解阻操作。

缺少计划或工期时可以展示关系图，但受影响路径的完成日期显示待确定。有未排期需求时，项目整体标明“排期不完整”，不能把已排期部分的结束日期当作整个项目的完成承诺。

## 历史数据迁移

2026-09-10 已核验完整运行库：36 个需求、198 个工作项。迁移后 19 个需求保留历史原文与出处，没有未关联来源；依赖、人员、进展及历史表与迁移前一致。

| 旧数据 | 迁移方式 |
|---|---|
| 待规划 | 转为未开始，保留已填资料 |
| 阻塞 | 按实际开始情况转为进行中或未开始；阻塞说明、时间和协调信息转入历史记录 |
| 已关联条款 | 原文、出处及已填写的实现范围并入对应需求或工作项的资料，不新建重复需求 |
| 未关联条款 | 列出迁移预览，由人核对哪些应创建需求；不默认丢弃或全部生成任务 |
| 待验收 | 按工作完成事实转为已完成；日期缺失的列入待核对清单 |
| 原验收、承诺和返工记录 | 保留历史，不伪造新的工作项、日期或验收事实 |
| 依赖、附件、进展、人员、布局 | 保持关联，核验端点语义变化对排期的影响 |
