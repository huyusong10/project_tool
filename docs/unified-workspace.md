# 统一项目工作区

## 使用方式

三个视角共用项目、特性、Phase、需求范围。首次进入显示特性清单，后续按账号和项目恢复上次范围和视角。

左上角 Logo 返回当前项目的项目层特性清单。固定概览条展示近 7 天完成、累计完成、推进中、Phase 交付和阻塞；展开浮窗查看近期完成项、交付安排和阻塞详情。

| 操作 | 行为 |
|---|---|
| 单击对象名称或行空白 | 打开共用资料面板，范围不变 |
| 名称旁的进入箭头 | 进入下一层，三个视角共同切换范围 |
| 展开箭头 | 原地展开，面包屑不变 |
| 行末省略号 | 打开固定尺寸的操作菜单 |
| 上一级、面包屑 | 进入指定祖先，保留视角 |
| 特性清单 | 直接创建、批量选择、拖拽排序和移动 |
| 关系图 | 维护依赖和布局，业务草稿统一预览、保存和处理冲突 |
| 进展表 | 按当前范围查看计划／实际双轨并更新进展 |

Phase 属于单个特性。跨特性的交付配合通过需求依赖表达。

清单勾选只选择当前对象。表头复选框选择当前可见对象，系统分组左侧有“选择本组全部需求”菜单。批量操作浮在表格底部，列宽不变。需求跨归属移动时追加到目标末尾，多选拖拽保持来源顺序。人工顺序支持拖拽手柄、Alt + 上下方向键和批量上移／下移；筛选或按名称、日期排列时禁用行间排序。

移动、排序使用独立事务，成功后可以撤销。撤销同时核对涉及的同级成员及版本；发生后续修改时整批拒绝。已推进 Phase 的移动填写原因，已交付 Phase 先重新打开。未知提交保留原请求，读取正式资料后明确核对，不自动重发。

清单的“新建”菜单随范围提供特性、Phase、需求和工作项入口。新建、编辑、展开和导入统一放在公共操作栏右侧；搜索和排序保留在筛选行。特性、Phase、需求、工作项和系统分组分别使用图标、颜色及行背景区分。

公共功能栏左侧显示面包屑和状态，右侧显示视角与操作。窄屏统一分为上下两行；撤销、重做和保存出现时不挤动其他区域。不因没有编辑按钮而显示“只读”。详情和概览浮窗、筛选与批量选择不改变导航和正文边界。

## 详情与问题跟踪

特性、Phase、需求、工作项与问题共用居中弹窗。默认宽 960px，高度不超过 760px，并随视口缩小；标题、栏目、操作栏固定，正文独立滚动。

| 对象 | 固定栏目 |
|---|---|
| 特性 | 概况、交付范围、资料、依赖、记录 |
| Phase | 概况、需求清单、资料、依赖、记录 |
| 需求 | 概况、工作项、资料、依赖、记录 |
| 工作项 | 概况、资料、依赖、记录 |
| 问题 | 进展、基本信息、记录 |

需求“工作项”栏目统一提供新增、人员与日期安排、排序和执行；更多菜单集中提供排序与低频操作。点击名称在当前弹窗切换对象，返回恢复栏目、滚动和输入。工作项使用自适应行布局，窄屏分行展示。

关闭和刷新保留当前账号、项目和对象的输入；“取消编辑”清除当前表单。提交结果未知时，原提交独立保存并先核对，不自动重试。详情网址使用 `detailId`、`detailTab`；图形选择使用 `pathNode`、`pathEdge`。

图形空白区域只选中，名称打开详情。拖拽、框选和连线不打开详情。工作项拖动显示对象预览；也可用更多菜单上移、下移，或空格提起、方向键移动、空格放下，Esc 取消拖拽。

问题列表保留完整优先级、状态与日期，空间不足时横向滚动整张表。进展快捷值为 20%、50%、80%、100%。项目经理选择 100% 后点击“保存并解决”，调用现有解决接口，一次提交进度、日期和说明；负责人仍可更新至 99%。经理降低进度时点击“保存更正”，追加更正记录。

已解决问题在“基本信息”修正标题、影响和解决日期，原历史保留。状态菜单仍负责挂起、恢复和重新打开。发生版本冲突或提交结果未知时保留输入，核对正式结果后再操作；访问失效时明确显示无法访问，不停留在加载状态。

统计分析和待办事项在“项目协作”导航下独立显示，保留当前项目。导航入口和分组标题统一为四字，包括项目空间、待办事项、人员权限。进展表的搜索和下拉筛选统一字号、字重、高度及左对齐方式。

## 概览与系统归类

概览统计正式数据，筛选不影响计数。显示需求完成数量、Phase 交付数量、阻塞需求数量；取消项不计入成果，归档完成项保留贡献。按阻塞来源合并影响需求，保留原分析排序和关键路径结果。

点击概览打开浮窗，不增加正文高度。浮窗显示未来 30 天、逾期、推进中及待交付批次；未定日期单列。特性和 Phase 可查看批次范围及需求执行阶段，需求层可查看工作项及预计完成。阻塞可以定位到当前层关系图。

“其他需求”以 `Feature.kind=other` 标识，固定置底。系统禁止改名、归档、删除、新建 Phase 或特性规划关系；保留历史 Phase 的处理入口。需求仍参加依赖、排期和统计。

## 接口与数据

| 接口 | 契约 |
|---|---|
| `POST /api/projects/:projectId/outline-order` | `kind`、`parentId`、完整同级 `items:[{id,expectedVersion}]`；返回当前顺序及 `undo` |
| `POST /api/projects/:projectId/requirement-placement` | 原输入兼容；维护目标人工顺序，附带 `undo` |
| `POST /api/projects/:projectId/outline-restore` | 提交 `undo.before/expected`，必要时填写 `reason` |
| `POST /api/projects/:projectId/features/archive-batch` | 任一所选特性不满足归档条件则整批回滚 |
| `GET /api/requirements/query?sort=manual` | 人工顺序；旧客户端默认仍按名称排序 |

上述写入通过现有操作注册表同步开放 MCP：`order_outline`、`update_requirement_placement`、`restore_outline`、`archive_features`。

迁移 `0034` 保留特性 ID、需求引用、布局和交付历史。需求初始顺序按原名称／编号自然顺序回填。启动及备份恢复均执行可重复的顺序初始化。

网址使用 `workspaceView`、`scopeType`、`scopeId`；资料选择单独保存。旧工作区和独立需求网址转换为对应范围，旧导入入口、提交原文和本地业务草稿继续保留。

## 验证入口

- `tests/workspace-navigation.test.ts`：层级、旧链接、概览范围、去重和多选顺序。
- `tests/workspace-outline.test.ts`：原子排序、移动撤销、版本冲突、归档和系统归类保护。
- `tests/workspace-migration.test.ts`：历史 Phase、交付快照和引用保留。
- `tests/responsive/workspace-frame.pw.ts`：布局坐标、固定列、类型区分、浮窗、窄屏和深色状态文字。
- `tests/responsive/unified-workspace.pw.ts`：三个视角、表单保留、创建、拖拽、异常提交、例会更新和导入。
- `npx tsx scripts/validate-workspace-migration.ts <旧数据库>`：对一致性副本迁移并逐表比对，不修改来源数据库。

独立预览使用 `project-manage-workspace` worktree、3281 端口、`.preview/workspace.db` 和独立会话 Cookie。配置脚本拒绝覆盖既有预览；登录资料保存在 `.preview/access.json`。

未指定 Phase 的需求归入特性下的“未分派阶段”分组，固定置底、默认折叠。清单、进展表与关系图使用相同名称和范围；分组不是正式 Phase，不参与交付批次数量，不改变需求归属、执行状态或统计。
拖拽虚影复用原对象的名称区或卡片标题区，保留原图标、颜色和字形，多选仅增加数量提示。
