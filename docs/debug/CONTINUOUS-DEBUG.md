## 工作顺序

每轮读取本记录及 Git 状态，选取可复现缺陷；先补回归，再修复、验证及提交。一次只处理明确的问题，避免反复运行无新增依据的全套检查。自动续跑间隔 30 分钟，直到用户要求停止。

| 项目 | 状态 |
|---|---|
| 直接需求普通进度降低、阻塞中提高进度 | 待复现与修复 |
| 直接执行及拆分后的计划趋势与公共计算不一致 | 待复现与修复 |
| 直接开始重读未更新前置关系版本 | 待复现与修复 |
| 实际日期更正绕过业务草稿检查 | 待复现与修复 |
| 验收入口展示的材料不一致 | 待核对 |
| 执行结果未知的核对规则 | 待核对 |
| 交付设置保存、阻塞说明入口 | 待核对 |
| 跨页面、画布、甘特、响应式与刷新恢复 | 按修改范围回归 |

既有证据见 `docs/dependency-paths/OPERATION-AUDIT.md`。用新的复现结果确认当前状态，不直接把历史推测当成缺陷。
