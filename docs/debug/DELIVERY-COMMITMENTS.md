## 使用入口

| 内容 | 入口与行为 |
|---|---|
| 项目交付承诺 | 项目设置、全局路径、需求交付设置 → 交付承诺；项目经理预览整个共享草稿后确认 |
| 预测核对 | 直接执行需求的概览按钮；工作项的更多菜单 → 预测依据与阻塞协调 |
| 阻塞协调 | 同一核对窗口选择协调人、下次核对日期或关联项目问题；加入草稿后整批保存 |

| 承诺比较 | 承诺窗口显示历史、范围与标准差异；需求信息和计划预览显示首次承诺日期及偏差 |
| 交付率 | 统计默认使用首次承诺；可选择最近确认或原有当前计划口径。无样本显示不可计算 |

## 业务定义

| 对象 | 定义 |
|---|---|
| 承诺 | 项目整体不可修改快照，包含确认后的交付范围、计划目标、标准、确认人和时间。后续确认追加记录并填写原因 |
| 首次承诺日期 | 需求首次纳入确认的日期目标；首次缺日期不从后续记录补齐 |
| 最近确认日期 | 验收前最后一份包含该需求的确认；有完整验收时间时按时间比较 |
| 统计样本 | 期间内已验收、有承诺日期且未撤出的需求。未验收延期、撤出／取消、无承诺和首次缺日期单列 |
| 完成度 | 工作完成比例；分解需求汇总工作项，说明记录不修改完成度 |
| 预测核对 | 剩余工作日或预计完成日期，独立于完成度、实际日期和确认计划 |
| 核对失效 | 返工、前置变化或预测过期保留原核对记录并提示重新核对，未知条件向下游传播 |
| 人员并发 | 其他正在执行的工作数量，可展开前 10 项及预计交付、关键路径提示并进入需求；不自动平移日期或提高优先级 |
| 阻塞协调 | 默认执行负责人，失效时由项目经理处理；关联问题沿用其负责人和核对日期。解决问题不自动解阻 |
| 范围核对 | 已确认承诺后新增、撤出或取消需求，现有行动提示项目经理核对。首次确认前不催办；再次确认后按新范围比较，不另算优先级 |

`executionCompletedAt` 表示真实工作完成，`acceptedAt` 表示验收，`observationEnd` 表示甘特观察截止。旧 `actualEnd` 保留兼容；新页面不把观察日期当成完成事实。

## 保存与恢复

- 编辑、预览不写正式数据。承诺、实体、估算、关系、布局、审计及回执在一个事务提交。
- 同一批次重复提交返回原回执；不同内容复用批次标识被拒绝。结果未知先查询原批次。
- 交付设置只加入实际修改的字段；预览包含项目已有草稿，不拆成部分保存。
- 名称、背景、链接和布局不阻止无关执行。同对象的执行敏感字段、删除及相关条件关系需要先核对。
- 执行后对整个撤销历史重新合并服务端基线。同字段、历史步骤或端点冲突逐项选择，不丢弃撤销记录。
- IndexedDB 格式保持兼容，旧会话草稿迁入成功后才清除；新增可选字段从服务端基线补齐。浏览器关闭前以本机保存完成状态为准。
- 单项命令收到异常响应时保留输入。版本变化后需要核对执行记录，不把相同内容当成本人操作成功。
