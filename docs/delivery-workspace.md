# 项目交付工作区

首页提供表格和关系图。两种视图共享范围、选中对象、详情操作和项目图形草稿。

| 范围 | 表格 | 关系图 |
|---|---|---|
| 项目特性 | 特性目标、Phase 标签、近期日期、关注事项 | 特性、Phase 标签、规划关系和实际依赖 |
| 单个特性 | Phase、当前阶段、负责人、日期 | 需求和实际依赖；特性内按 Phase 排列区域 |
| 单个需求 | 工作项阶段、负责人、计划、进度 | 工作项、里程碑和执行依赖 |

项目只保留特性入口，按“特性 → 需求 → 工作项”下钻。每条需求归入一个特性；未指定时归入普通的“其他特性”，Phase 仍可暂不安排。

单击打开右侧详情；双击或“进入”下钻。详情支持宽面板，窄屏占满屏幕。Phase 标签可以直接选择；阶段数量可以筛选需求。近期目标日期取未交付 Phase 的最早日期，同日 Phase 一并列出。

## 日常操作

- 特性详情维护目标、文档、人工评估和 Phase。归档与恢复位于更多操作。
- Phase 详情维护范围、日期和关注说明，安排需求，确认交付或重新打开；历史按需展开。
- 需求详情沿用独立需求页面的资料、模板、工作项设置、提测、进度、完成、返工和历史操作。
- 表格多选需求后使用“批量安排 Phase”。系统校验全部需求版本，失败整批回滚。
- 关系图拖动只改位置。归属通过表单修改，推进后的调整填写原因。

## 草稿与执行

图形结构、依赖、属性和布局使用项目级草稿。表格读取相同草稿投影。无效字段也保留在本机；切换视图或范围不自动提交。保存、撤销、冲突处理和待核对回执沿用已有流程。

执行记录、提测和交付仍为独立操作。临时对象保存前不能执行。Phase 操作检查范围内需求及前置条件的业务草稿；纯布局不阻塞执行。正式交付快照不会被草稿投影改写。

特性、Phase 和需求资料的未提交表单保存在当前账号、项目、对象的本机会话中，连同原版本恢复。待核对请求单独保存，先核对原回执或最新记录。

## 链接与布局

| 参数／范围 | 约定 |
|---|---|
| `/` | 默认 `view=features&mode=table` |
| `view` | `features / feature / project / requirement` |
| `mode` | `table / graph` |
| 定位 | `featureId / requirementId / phaseId / pathNode / pathEdge` |
| 旧 `/features` | 转为表格，`feature` 转为特性选中项 |
| 旧 `/paths` | 转为关系图，保留筛选、对象和编辑恢复参数 |
| Phase 坐标 | `feature-phase:<featureId>:<phaseId或unassigned>` |

原 `features`、`feature:<id>`、`requirement:<id>` 布局保留。新范围保存区域内相对坐标。区域宽度、横向顺序和画布位置由展示层计算；没有新坐标时按旧位置顺序初始化，明确保存后才写入。

图节点随内容增高，Phase 区域按节点边界展开；拖动只能在所属区域内调整位置。连线避开 Phase 标题。初始视图保持可读字号，“适配视图”可查看完整关系。

Phase 筛选保留直接跨范围依赖的外围节点。筛选、Phase 排列和区域边界均不参与排期或路径计算。新布局沿用批次预览、版本、权限和回执校验，REST 与 MCP 共用服务。筛选后保存仍保留隐藏节点坐标。

`get_path_graph` 的特性节点返回简要 Phase 标签，特性范围返回 `phaseRegions`，需求节点返回 `featureId/phaseId`。`view=feature` 可以传 `phaseId`，完整 `analysis` 保持原项目分析。图节点不携带交付历史快照；详情从正式资料读取。

迁移 0033 将没有特性的需求归入所属项目的“其他特性”，保留原 ID、执行事实和交付记录；不新增业务实体表。隔离预览为 `http://127.0.0.1:3260`，数据库、备份、会话、技能同步和固定构建位于 worktree 的 `.preview`。
